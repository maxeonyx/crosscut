Why

Every project needs to track many shared requirements. CrossCut gets your agent to advocate for them.

What it isn't

QUALITY REPORT62%
securityFAIL
docsPASS
vibesPENDING

No scores. A map full of gaps is a good map.

Cheapest check wins

  1. Design it away.
  2. An existing tool.
  3. Your own script, with fixtures.
  4. A prompt, with fixtures.

What it looks like

$ crosscut check
staying-current/data-cli: (none) → missing: CLI has no self-updater; installed copies stay where they were installed
staying-current/ops-cli: (none) → yes: CLI depends on self_update
staying-current/photo-server: (none) → missing: docker-compose.yml pins images and nothing proposes upgrades
version-visibility/billing-web: (none) → yes: site publishes version.json with a commit
…
14 cells checked: 14 changed, 0 could not run      # no model involved

$ crosscut check --agentic recoverable-state      # one agent per cell
recoverable-state/photo-server: (none) → missing: holds photos (/srv/photos) and a catalogue
  (vault-db volume) with no backup, no off-machine copy, and no sign of a restore

$ crosscut test
18 fixture cells: 18 as expected, 0 not            # the checks, checked

$ git diff crosscut/                             # the history of the map

The whole format

crosscut/
  projects                       projects/*
  concerns/staying-current/
    concern.md                   user stories, what it looks like here, decisions
    check                        prints "yes: …" for one project
    fixtures/basic/              invented projects + expected answers
    observed.tsv                 written by the tool, committed

Plain files. Your decisions stay yours. Git is the history.

Get it

cargo install --git https://github.com/maxeonyx/crosscut --locked
crosscut install-skill      # Claude Code, Codex, OpenCode
