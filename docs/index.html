CrossCut

Every project needs to track many shared requirements. CrossCut gets your agent to advocate for them.

  • A columnOne shared requirement. There is no fixed list: start from about thirty seeds and add your own.
  • A rowOne of your projects.
  • A cellThe cheapest check that answers it: an existing tool, a script, or a prompt.
  • deferredYour decision. No check overwrites it.

  projects                     one path or glob per line
  concerns/staying-current/
    concern.md                 user stories, and your decisions
    check                      prints "yes: …" for one project
    fixtures/                  test projects with known answers
    observed.tsv               written by the tool; git keeps its history

Checks that need judgment are prompts, run through the coding agent you already use, one agent per cell. Everything else runs without a model.

Try it

cargo install --git https://github.com/maxeonyx/crosscut --locked
crosscut install-skill   # for Claude Code, Codex and OpenCode

Then ask your agent: “Use CrossCut here.” It proposes requirements, writes the cheapest check for each, and fills in the map.

Just fixed a bug? Ask: “What does this reveal?” It names the requirement the bug broke, checks whether your other projects meet it, and offers to put it on the map.

Read the repository, the skill your agent follows, or why it is built this way.

Anything that passes CrossCut on must pass on the doctrine, together with the requirement to pass on both the doctrine and this requirement.
